Esta é uma documentação técnica detalhada do projeto SAP Suprimentos Pro (SAE), estruturada para servir como guia de manutenção e referência para futuras expansões. O projeto utiliza a arquitetura padrão SAE (Sistema Apollo Enterprise), focada em alta performance dentro do ecossistema Google Workspace.1. Visão Geral da ArquiteturaO sistema opera sob o modelo de Single-Page Application (SPA) hospedada no Google Apps Script.Backend: Google Apps Script (V8 Engine) - Código.js.Frontend: Vue.js 3 (via CDN) integrado em um arquivo único - index.html.Banco de Dados: Google Sheets (Planilhas Google) atuando como banco de dados relacional simulado.2. Estrutura de Dados (Google Sheets)O "banco de dados" é composto pelas seguintes entidades (abas):AbaDescriçãoChaves PrincipaisinsumosCadastro mestre de materiais.uuid, codigo_axestoque_snapshotRegistro de saldos em pontos específicos no tempo.uuid, codigo_ax, snapshot_anterior_idmovimentacao_apuradaLog de entradas e saídas processadas para cálculo de consumo.uuid, codigo_ax, tipo_movimentohistorico_posicao_estoque_mensalDados consolidados mês a mês para análise de tendência.uuid, codigo_ax, competencia3. Documentação do Backend (Código.js)Funções de Interface (API)doGet(): Ponto de entrada que renderiza o index.html. Define o título da aba e configurações de viewport para mobile-first.getDashboardData(): Função principal de "Busca de Dados".Entrada: Nenhuma.Saída: Objeto JSON contendo: insumos, projesp (projeções), movimentacoes (últimas 20), historico (pivotado) e stats.Lógica: Consolida informações de 4 abas diferentes, calcula médias de consumo e gera previsões de ruptura em tempo real.registrarSaida(codigo_ax, quantidade):Entrada: Código do item e valor da saída.Saída: Confirmação de sucesso e novo saldo calculado.Lógica: Localiza o último saldo no estoque_snapshot, subtrai a quantidade e insere uma nova linha com status PENDENTE_APURACAO.Funções Auxiliares (Privadas)_readSheet(sheet): Converte um intervalo da planilha em um Array de Objetos JS usando a primeira linha como chave (Headers)._calcularMediasSaida(movs): Filtra movimentações de saída dos últimos 30 dias para extrair o consumo médio diário real._formatarHistorico(hist): Realiza um "Pivot" nos dados de histórico mensal, transformando linhas verticais em uma estrutura de 12 meses (Janeiro-Dezembro) para o gráfico._calcularStatsGerais(projesp, medias): Sumariza totais financeiros/quantitativos para os cards do topo do Dashboard.4. Documentação do Frontend (index.html)Stack TecnológicaVue 3 (Composition API): Gerenciamento de estado e reatividade da UI.Tailwind CSS: Estilização utilitária e responsividade.Chart.js: Renderização de gráficos de linha para análise de tendência.Lucide Icons: Biblioteca de ícones vetoriais.Componentes e Estados (Setup)currentTab: Controla a navegação entre Dashboard, Histórico, Movimentação e Lançamentos.loading: Gatilho para o "Skeleton/Loader" estilo Google que bloqueia a UI durante chamadas assíncronas.projesp: Lista reativa que alimenta a tabela de previsão de ruptura.chart: Instância do Chart.js que é destruída e recriada ao filtrar dados.5. Contrato de Comunicação (Ida e Vinda)O projeto utiliza o protocolo google.script.run para comunicação assíncrona.Fluxo de Carga (Request Data):Frontend chama getDashboardData().Backend lê as planilhas -> Processa médias -> Devolve JSON.Frontend recebe via .withSuccessHandler(), atualiza as variáveis do Vue e renderiza o Gráfico.Fluxo de Transação (Save Data):Frontend envia codigo_ax e quantidade via registrarSaida().Backend valida o item -> Calcula novo saldo -> Grava na Planilha -> Retorna OK.Frontend limpa o formulário e chama o refresh() para atualizar os saldos na tela.6. Regras de Negócio ImplementadasCálculo de Cobertura: Saldo Atual / Média Diária (30 dias). Se a média for zero, o sistema retorna 999 dias (Estável).Alerta de Ressuprimento: Um item entra em estado crítico se Saldo <= Ponto de Ressuprimento.Padrão de Data: Todas as datas de sistema são gravadas em ISO 8601 (YYYY-MM-DDTHH:mm:ss.sssZ) para evitar erros de fuso horário entre o Script e a Planilha.Segurança de Registro: Cada linha gravada inclui o e-mail do usuário ativo (Session.getActiveUser().getEmail()) para fins de auditoria.
